PR #28659｜主线 / main

CSV 块扫描器通过 SWAR 检测块内是否全为 ASCII，并跨块跟踪字符串状态；对完全位于 ASCII 块内的字符串，写入结果向量时跳过 UTF-8 校验。

重要性与适用范围：主要适用于读取 ASCII 字符串列的 CSV 查询与导入，可减少逐值校验的重复扫描工作；优化取决于字符串涉及的块是否全部为 ASCII，而非仅看字符串自身内容。

官方原文证据（保留基准及适用条件）：
SwarBlock::HasHighBits now checks in one SWAR pass whether any byte of the block has its high bit set. The first block has no such byte, so block_ascii is true. As the scanner walks the block, value_ascii tracks whether every block holding a byte of the current value is ASCII. This state carries across block edges.

For SELECT b, c FROM read_csv(...), both projected columns are strings. The delimiter at byte 5 ends ann, and value_ascii is true. The scanner sets ascii_value on the result around the AddValue call, so AddValueToVector stores ann without calling Utf8Proc::IsValid. It clears the flag after the call.

The quote at byte 6 opens the next value. The comma at byte 8 lies inside the quotes and is passed over. The closing quote at byte 11 and delimiter at byte 12 end x, y, which takes the same path and skips validation. At row ends, the flag is set around AddRow in the same way. In both cases, it applies only to the value being added.

PR #131569｜主线 / master

优化 Compact 数据分片的多阶段 PREWHERE 读取路径：只要前序步骤完全过滤掉某个粒度，后续步骤和最终读取便跳过该粒度，不再受读取块大小影响。

重要性与适用范围：适用于 Compact 分片上能由前序 PREWHERE 步骤完全排除部分粒度的查询，可减少后续列读取中的重复工作；Wide 分片仍保留原有处理策略，不受此次优化影响。

官方原文证据（保留基准及适用条件）：

Changelog entry (a user-readable short description of the changes that goes into CHANGELOG.md):

A multi-step PREWHERE over Compact parts no longer reads the granules that an earlier step filtered out completely again in its later steps and in the final read, whatever the read block size. For the query from #131382 this reads 45% fewer compressed bytes and runs up to 1.5x faster. Closes #131382.

Description

On Compact parts, a granule that an earlier PREWHERE step filtered out completely was read again by every later step and by the final read, unless the emptied granules were more than half of the rows of one read. How many granules one read covers is chosen by the block size predictor, so query_plan_remove_unused_columns = 1 (it narrows the PREWHERE output, and reads grow from 1 to 4 granules) made the query in #131382 read every primary-key-selected row in every step.

ReadResult::optimize removes fully filtered granule tails from rows_per_granule only when 2 * total_zero_rows_in_tails > filter.size() (d1ddb127).
