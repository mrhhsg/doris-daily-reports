将列缓存扩展到 Parquet 文件读取：本地文件、S3/Azure 等对象存储和数据湖表经元数据感知创建器的读取可使用缓存；缓存项保存一个 row group 的完整输出列，重复查询热点数据时跳过列块的读取、解压和解码。

PR #126253｜主线 / master

利用ColumnCompressed保留的压缩部件，让Memory表读取String的size、Array的size0、Nullable的null、Tuple元素及Map的keys、values和size0子列时仅解压对应部件；同一列与其子列同查时每块只解压一次。

重要性与适用范围：面向使用compress=true的Memory表且查询只读取上述子列的场景，避免整列解压并减少重复解压；其它子列仍回退整列，收益取决于查询是否命中这些子列。

官方原文证据（保留基准及适用条件）：
ColumnCompressed now keeps the compressed parts it was built from (getParts). They share its data, so byteSize and system.tables.total_bytes do not change. tryGetSubcolumnFromBlock maps the subcolumns listed above to parts and falls back to the whole column for anything else. The mapping takes the type instead of being a ColumnCompressed::decompressSubcolumn(name), because only DataTypeTuple knows the element names. The Nested sizes path decompresses only the offsets of the stored sibling.

Master also decompressed a column once per requested name, so s, s.size decompressed s twice. Such a column is now decompressed once per block.

The setup from the issue (8M URLs from hits_0.parquet), Release build, best of 5, max_threads = 8:

query master this PR

count() WHERE empty(URL) 0.030 s 0.010 s
avg(cityHash64(URL)) 0.042 s 0.042 s
count() WHERE NOT ignore(URL, URL.size) 0.057 s 0.031 s

The same table with compress = 0 takes 0.003 s for avg(length(URL)). On synthetic data n.null, t.x and m.keys go from 0.010, 0.019 and 0.037 s to 0.003, 0.011 and 0.024 s.

PR #124907｜主线 / master

优化外部 IN 子查询的磁盘集合：按值顺序保存数值、日期、短 FixedString 和元组，打包邻近键，合并读取邻近块且不解压，用 Bloom 过滤跳过块，缓存查找块，并对每块不同键只探测一次。

重要性与适用范围：适用于使用 IN 子查询且集合可能溢写到磁盘的查询；max_bytes_ratio_before_external_set 默认 0.5，使集合在查询内存超过服务器或用户限制剩余内存一半时落盘。本改动提升此类集合的构建和查找性能，并提供 Bloom 过滤与缓存的内存上限设置。

官方原文证据（保留基准及适用条件）：
Sets of IN with a subquery spill to disk by default: max_bytes_ratio_before_external_set now defaults to 0.5, so a set spills once query memory exceeds half of the memory that the server or user memory limits leave. Set it to 0 to keep such sets in memory. Sets on disk are built and looked up several times faster: they keep numbers, dates, short FixedString values and tuples of them in order, pack close keys, read neighboring blocks together without decompression, skip blocks with Bloom filters, cache the blocks that lookups read, and look up each distinct key of a block of rows once. The new settings max_bytes_for_external_set_bloom_filter and max_bytes_for_external_set_cache, 128 MiB each by default, limit the memory of the Bloom filters and of the cache.

PR #80396｜主线 / main

优化H3_PolygonToCells：≥128顶点、纬度绝对值≤70度且经度跨度≤90度的分量改用递归中心填充，其余走标准路径；单环POLYGON用纯GEO helper复用S2校验，免去构造被丢弃的S2Loop/S2Polygon；单分量就地紧凑输出并批量追加。

重要性与适用范围：运行时性能优化，针对H3_PolygonToCells处理高顶点复杂多边形的填充与单环校验路径，减少S2Loop/S2Polygon构造与输出去重开销；递归填充仅用于满足顶点数、纬度与经度跨度阈值的分量，其余走标准polygonToCells。

官方原文证据（保留基准及适用条件）：
Use recursive center filling from pinned H3 4.5.0 for components with at least 128 input vertices, absolute vertex latitude at most 70 degrees, and longitude span at most 90 degrees. Small, polar, wide and antimeridian-crossing components use standard polygonToCells. Preserve the standard maxPolygonToCellsSize preflight and output slab; E_MEMORY_BOUNDS clears the slab and falls back to standard polygonToCells.

For a nonempty single-ring POLYGON, validate the same mapped coordinates, mapped closure and adjacent-duplicate cleanup through a pure GEO helper. It applies S2's unit-length/duplicate/antipodal checks and official robust self-intersection validator using a polygonal S2LaxLoopShape. This avoids constructing, normalizing and bounding a discarded S2Loop/S2Polygon. Holes and every MULTIPOLYGON retain spherical_is_valid. Existing GeoPolygon construction preserves its preparation, parse statuses, IsValid and Normalize behavior.

For a sole nonempty component, move and compact its output slab in place and avoid redundant single-component deduplication. Preserve ordered union deduplication for multiple nonempty components. Do not redundantly re-validate cells returned by H3 for a validated polygon; compact H3_NULL slots. Append polygon cells in bulk through H3ArrayBuilder::append, retaining the cumulative array-offset check.
