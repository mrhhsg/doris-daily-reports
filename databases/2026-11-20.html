PR #29079｜主线 / main

将指定常量日期部分的date_part绑定到对应一元函数，使优化器识别其单调性，让适用的date_part及EXTRACT过滤条件转为日期范围并下推扫描。

重要性与适用范围：适用于按年份等单调日期部分过滤的查询，可通过范围下推裁剪行组，避免原先逐行计算过滤表达式；优化依赖日期部分的单调性，并非所有日期部分均适用。

官方原文证据（保留基准及适用条件）：
Fixes #28898. This is one of the two PRs that replace #28901. The original change is from @mrouvroy-floe, and the first commit here is theirs.

Problem

A filter on year(d) is rewritten into a range on d, which is pushed into the scan and prunes row groups. The same filter written with date_part or EXTRACT is not, so it is evaluated on every row. Results are correct, only the pruning is missing.

CREATE TABLE d AS SELECT (DATE '1970-01-01' + INTERVAL (range) DAY)::DATE AS dt FROM range(500000);
EXPLAIN SELECT count(*) FROM d WHERE year(dt) = 2020;
-- Filters: (dt >= '2020-01-01'::DATE) AND (dt <= '2020-12-31'::DATE)
EXPLAIN SELECT count(*) FROM d WHERE date_part('year', dt) = 2020;
EXPLAIN SELECT count(*) FROM d WHERE extract(year FROM dt) = 2020;
-- Filters: "year"(dt) = 2020

With a constant part, date_part stayed a date_part call that was patched at bind time to behave like the unary function (year, epoch, ...). The patch set the callback and the statistics, but not the argument properties, so the optimizer didn't know the call is monotone.

Fix

date_part with a constant part now binds to the unary function itself. The per-part callback and statistics switches are gone, and the call gets everything the unary function has.

PR #28967｜主线 / main

优化器为直接列参数的 first、last、any_value 及 arbitrary 保留源值域，并约束当前值域估计，减少 DISTINCT ON 或显式分组后连接估计膨胀导致的不良连接顺序。

重要性与适用范围：适用于参数类型与排序规则匹配、且无法证明分组为单例的内置取值聚合，可改善后续连接规划；有序改写及聚合状态导出维持原行为，不代表所有数据分布都能受益。

官方原文证据（保留基准及适用条件）：
DISTINCT ON preserves non-grouping outputs using first(). After #28731, the optimizer can forward input domains for proven singleton groups. The unconstrained CTAS in #28615 has no such proof, so its aggregate still receives a cardinality-derived domain. This can inflate downstream join estimates and change join order. Explicit first(k) GROUP BY ... has the same problem.

The existing singleton-group rule takes precedence. When that rule cannot forward the input domains, the optimizer recognizes the bound built-in implementations of first, last, and any_value, including the arbitrary alias, by their private rewrite callbacks. For a direct column argument with matching type and collation, it keeps the source total domain and caps the heuristic current domain by the input domains and output cardinality. Ordered rewrites to other implementations and aggregate-state exports retain their existing behavior. Selected outputs carry no structural uniqueness or SEMI/ANTI evidence.

Fixes #28615.

SELECT i AS eid, i % 100000 AS k FROM range(5000000) t(i);

调整 Iceberg 删除文件缓存的条目判等与哈希逻辑，将条目在清单中的行位置纳入标识，使同一删除文件的重复存活条目分别保留，避免缓存因条目数不匹配而反复失效。

重要性与适用范围：适用于删除清单中包含重复删除文件条目的 Iceberg 扫描，可避免每次读取都丢弃缓存、重新加载并回退到原生清单读取路径；查询结果语义保持不变，收益限于此类清单的缓存复用。

官方原文证据（保留基准及适用条件）：
A delete manifest can list the same delete file more than once: a retried row delta commits the same delete file in a second snapshot, and a later delete manifest merge copies both entries into one manifest without deduplication. The manifest's added + existing count includes both entries, but DeleteFileWrapper identified a cached delete file by path and content offset only, so the two entries collapsed into one:

delete manifest entries: d, d -> added + existing = 2
cached set: {d} -> size 1!= 2 -> dropped on every read, refilled on every scan

Results stay correct because the fallback reads the manifest natively, but such a manifest is never served from the cache, and every scan logs Dropping incomplete Iceberg manifest cache entry.
