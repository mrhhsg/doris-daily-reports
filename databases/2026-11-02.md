A catalog may override the new \`SchemaCatalogEntry::Scan(ClientContext &, SchemaScanInfo &)\` to avoid the listing, for example a remote catalog answering a \`table\_name\` equality with a single lookup instead of listing the schema. The scanner re-checks every entry the schema hands back, so an override can only lose the saving, never change the result.

\`duckdb\_columns()\` additionally gains the schema-level pruning from \#27291, which it did not have before.

[PR \#28231｜主线 / main](https://github.com/duckdb/duckdb/pull/28231)

贪心连接顺序枚举器在首个方向被拒绝时尝试反向组合，避免因LEFT、SEMI或ANTI连接的方向限制遗漏有效候选，导致优化器保留原始连接树。

重要性与适用范围：适用于达到贪心连接顺序枚举阈值的查询；原始连接树对ANTI连接的估算可能阻碍公共子计划优化器物化重复子查询，使扫描保持单线程，此改动针对这一优化障碍。

官方原文证据（保留基准及适用条件）：
The greedy join order enumerator emits each candidate pair in one orientation only, with a newly merged set always on the right. \`LEFT\`, \`SEMI\` and \`ANTI\` joins are only valid in one orientation, so a valid pair could be rejected. When no candidate was left, the optimizer kept the original tree unchanged. That tree estimates an \`ANTI\` join at its full left input, which can stop the common subplan optimizer from materializing a repeated subquery and leave the scan single-threaded. Since https://github.com/duckdb/duckdb/pull/28016 this affects any query at or above \`approximate\_join\_order\_threshold\`.

The greedy enumerator now tries the reverse orientation when the first is rejected.

Should resolve: https://github.com/duckdblabs/duckdb-internal/issues/11679

[PR \#28209｜主线 / main](https://github.com/duckdb/duckdb/pull/28209)

优化完全拆分存储的 VARIANT 缺失键提取：以三态结果区分路径不支持与键不存在，后者直接返回常量 NULL，避免回退到通用提取并还原整个向量。

重要性与适用范围：适用于完全拆分且请求键不在拆分类型中的读取，可省去无意义的整向量还原工作；存在未拆分余部或其他不支持的情况仍保留原有回退，不改变这些路径。

官方原文证据（保留基准及适用条件）：
\`TryFromShreddedExtract\` only takes the shredded fast path when the vector is fully shredded, i.e. when there is no unshredded remainder. Inside \`TryShreddedExtractRecursive\`, walking the shredded \`typed\_value\` STRUCT for the requested key and not finding it returned \`false\`, which the caller interpreted as "this path is not supported" and fell back to \`VariantUtils::VariantExtract\` -\> \`RecursiveToUnifiedFormat\` -\> force-unshred of the entire vector.

That is unnecessary work: if the vector is fully shredded and the key is absent from the shredded type, the key provably cannot exist in any row. Instrumenting the call site on a 2M row table confirmed the full fallback rate:

| key | extract chunks | fallbacks |
|---|---|---|
| \`v.a\` (shredded) | 0 | 0 |
| \`v.zzz\` (not shredded) | 960 | 960 |

The \`v.a\` case never reaches this code because the projection pushdown extracts it in \`VariantColumnData::ScanWithCallback\`.

\#\# How

Replace the \`bool\` return of \`TryShreddedExtractRecursive\` with a tri-state \`ShreddedExtractResult \{ SUCCESS, NOT\_SUPPORTED, KEY\_NOT\_FOUND \}\` so the caller can distinguish "cannot do this" from "the result is definitively NULL". On \`KEY\_NOT\_FOUND\` emit \`result.Reference(Value(LogicalType::VARIANT()), count\_t(count))\`.

[PR \#128284｜主线 / master](https://github.com/ClickHouse/ClickHouse/pull/128284)

扩展全量排序下小规模 MergeTree 读取的流数保护逻辑，穿透 UNION ALL、ARRAY JOIN、IN 子查询及部分连接路径，保持默认读取流数，避免额外流扩大排序归并开销。

重要性与适用范围：适用于读取结果进入不带 LIMIT 或 PARTITION BY 的全量排序场景，减少无益并行对单一归并阶段的负担；仅调整读取流数，不遍历连接构建侧，且保留并行连接的读取扩展策略。

官方原文证据（保留基准及适用条件）：

The guard walked only \`Expression\`/\`Filter\` steps, so a read reaching the sort through \`UNION ALL\`, \`ARRAY JOIN\`, an \`IN\` subquery or the probe side of a join was still spread (\#128250).

Parallel joins (\`parallel\_hash\`, \`grace\_hash\`) resize the probe to \`max\_streams\` and keep the spread read; build sides are never walked. Only the read's stream count changes.
