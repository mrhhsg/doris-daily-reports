Avoid prolonged aggregate lookup skipping after short unique runs
A short run of unique grouping keys can cause one local hash-table fill to disable lookups for roughly another million rows. When duplicates return, this retains unnecessary aggregate rows and increases memory usage.

Require both the latest fill and decayed recent history to show less than 5% row reduction before skipping lookups. Choose the retry interval as clamp(materialized_rows / 8, 128K, 1M) input rows, checked when the local table fills or encounters memory pressure. Lookup decisions remain active when HLL is disabled or aggregation becomes external. No setting is added.

PR #29128｜主线 / main

统一函数序列化时的目录和模式名称，使执行计划及其深拷贝具有相同签名，让公共子计划优化器识别并共享窗口自连接中的重复聚合输入，避免重复扫描和分组聚合。

重要性与适用范围：适用于先分组聚合、再用窗口聚合计算总额占比或分区汇总的查询，可减少重复计算；是否共享仍由既有公共子计划优化规则决定，窗口自连接改写本身不变。

官方原文证据（保留基准及适用条件）：
A window aggregate over the whole partition is rewritten by the window self-join into input JOIN (SELECT keys, agg FROM input GROUP BY keys) (a cross product without PARTITION BY), with a deep copy of the input below the new aggregate. When the input is itself an aggregate, as in the "share of the total" shape

SELECT customer, sum(amount) AS total, sum(amount) * 100.0 / sum(sum(amount)) OVER () AS pct
FROM sales GROUP BY customer;

the grouped aggregate and the scan below it are computed twice. The common-subplan optimizer is there to share exactly this (it materializes repeated subplans that end in an aggregate), but it never recognises the copy: LogicalOperatorDeepCopy is a serialization round trip, the scan function of a table is bound as seq_scan, and it comes back from the round trip as system.main.seq_scan, the name the deserializer resolves it with. The two scans serialize to different bytes, so the plan signatures of a plan and of its own copy differ.

This PR writes a function under the name it is read back with (FunctionSerializer resolves a missing catalog / schema on both sides the same way), so that serializing a function before and after a round trip gives the same bytes. A plan and its copy then have equal signatures, and the existing rules of the common-subplan optimizer decide whether to share them. Nothing changes in the window self-join itself.

PR #129502｜主线 / master

官方原文证据（保留基准及适用条件）：

Changelog entry (a user-readable short description of the changes that goes into CHANGELOG.md):

PR #84189｜主线 / main

针对排序键与主键不同的范围分布主键表，静态 INSERT OVERWRITE 自用临时分区在拆分时为空且此后无提交时，跳过 CLEANING 阶段的 UNSHARE 触发与等待。

重要性与适用范围：减少空临时分区预拆分对压缩调度器的依赖，避免覆盖写入因无必要的压缩等待而延迟；也适用于物化视图刷新，但不扩展到普通空分区或拆分后已有提交的分区。

官方原文证据（保留基准及适用条件）：

  • CLEANING does not wait for UNSHARE on an INSERT OVERWRITE temporary partition whose children inherited nothing. After the wait for earlier transactions, a pinned partition is neither triggered nor waited on when it is a temporary partition that a running static INSERT OVERWRITE (a materialized view refresh included) created for its own write and has not swapped in yet (InsertOverwriteJobMgr.isTmpPartitionOfRunningStaticJob), the split read version 1 (commitVersion == PARTITION_INIT_VERSION + 1: the parent had no rowset, sstable, DCG or IDG to share), and nothing has committed to it since (nextVersion == commitVersion + 1). The resharding tablets are unregistered under the same table lock as the check, so no commit lands in between.
