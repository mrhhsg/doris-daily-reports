官方原文证据（保留基准及适用条件）：
## Problem
Batch insert buffers collections that are smaller than a row group until every earlier batch has finished. Only then can they be merged into full row groups and written out. Merges are scheduled in one place: `AddCollection`, when a thread hands over a finished batch. That call uses the thread's own copy of the minimum batch index, which was last updated when the thread started that batch and is often behind the global minimum. Advancing the minimum (`UpdateMinBatchIndex`) wakes blocked threads but schedules no merges.

So batches that become eligible when the minimum advances stay buffered until some thread finishes another batch with a newer minimum. Under memory pressure, threads not on the minimum batch block. When woken, they find no merge tasks to run, and they block again while the buffer keeps growing.

In the repro below, after the minimum jumps from batch 3 to batch 10, batches 4–9 wait 10.7s before their merges are scheduled, and buffered memory grows to 1.1GB.

## Fix
When a thread runs out of memory, it now calls `ScheduleMergeTasks` with the global minimum batch index before running pending tasks and blocking. Waiting threads then schedule and run the merges for every batch that has become eligible, which frees the memory.

[PR #82798｜主线 / main](https://github.com/StarRocks/starrocks/pull/82798)

优化范围分布主键表的 tablet 合并路径，按水位分类复用主键索引 SST：跳过范围下方的冗余文件，转换范围内文件，并在安全条件下调低范围上方文件的水位。

重要性与适用范围：适用于全量压实或拆分后再合并等索引水位超出源范围的场景，可减少合并后首次加载时的索引冷重建；若调低水位造成同源水位冲突，仍回退重建。

官方原文证据（保留基准及适用条件）：
BE only, in `tablet_merger.cpp`. The run layout, `next_rowset_id` growth and the int32 headroom are unchanged; so are the merge input contract, admission, UNSHARE and the refusal of shared or range-less SSTs. Per source, each SST is classified by its watermark relative to the run [B, E):
- **Below B: left out.** Every entry pointing to a live row is inside the run and compaction never keeps a newest entry pointing to a dropped rowset, so such an SST only holds shadowed entries and tombstones, and can only be a prefix of the list (the merge input check already refuses decreasing watermarks). Leaving it out changes no lookup. It is recorded once as a shared orphan of the merged tablet.
- **Inside the run: translated** as before.
- **At or above E: translated, with the watermark lowered** to the translated position of E - 1 with all low 32 bits set, as long as that does not make two originally different watermarks of the same source equal. Index compaction breaks same-version ties by SST watermark and prefers the tombstone, so such a tie falls back to the rebuild. Keys of different sources never overlap, so ties across sources are harmless.
