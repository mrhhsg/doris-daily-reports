重要性与适用范围：该优化改变运行时连接执行路径，适用于析取等值连接；仅支持 2–16 个等值分支，覆盖普通与 NULL 安全等值，FULL JOIN 独立检查两侧未匹配行以减少重复生成。

官方原文证据（保留基准及适用条件）：
Disjunctive equality joins currently use a blockwise nested-loop join even when each equality can use a comparison join. This adds an optimizer pass for INNER, LEFT, RIGHT, FULL OUTER, SEMI, and ANTI joins whose condition is an OR of 2–16 cross-input equalities, including \`IS NOT DISTINCT FROM\`.

For pair-producing joins, each equality becomes a comparison join. Later branches exclude pairs already accepted by earlier branches; \`UNION ALL\` preserves duplicate occurrences. Ordinary equality exclusions use \`lhs IS NULL OR rhs IS NULL OR lhs != rhs\`, allowing UNKNOWN through while letting statistics remove unnecessary NULL checks. NULL-safe equality uses \`lhs IS DISTINCT FROM rhs\`. These checks use the complete comparison operands, including nullable computed expressions. Outer joins append unmatched rows from anti-join chains. FULL JOIN checks unmatched rows independently on each side, so it does not regenerate the matched pairs to find unmatched RHS rows. SEMI uses a MARK-join chain and ANTI uses an anti-join chain.

该 PR 让 Iceberg 的 remove\_orphan\_files 和 expire\_snapshots 跳过已收集的 manifest，避免为每个快照重复读取同一清单，使读取量随不同 manifest 数而非快照数二次增长。

重要性与适用范围：对 append-only Iceberg 表执行这两个 ALTER TABLE ... EXECUTE 维护命令时，该优化避免重复读取 manifest，降低文件打开与耗时；适用于元数据缓存开启或关闭、快照数较多的场景，可缓解清单读取随快照数二次增长的问题。

官方原文证据（保留基准及适用条件）：
\`remove\_orphan\_files\` builds its reachable set by walking every snapshot and reading every manifest in its manifest list (\`collectSnapshotReferencedFiles\`). Iceberg carries unchanged manifests forward, so on an append-only table snapshot k lists k manifests and N snapshots cost N(N+1)/2 manifest reads. \`expire\_snapshots\` had a private copy of the same loop for its retained snapshots. 重构H3\_Resolution和H3\_ToParent运行时求值路径：非NULL输入直接写入预分配输出缓冲，避免逐行追加和空值检查；验证后从索引字段读取分辨率并以常量位操作构造父级，同时预计算父级掩码。

重要性与适用范围：该改动直接优化H3标量函数求值，适用于处理H3 cell及目标分辨率的查询，尤其无NULL输入；保留isValidCell校验、错误优先级和可空回退，数组与地理函数不变。

官方原文证据（保留基准及适用条件）：
Fixes \#80522

\#\# Why I'm doing:

H3\_Resolution and H3\_ToParent spend avoidable time constructing output columns. H3\_ToParent also uses a digit-by-digit parent conversion even after the cell and target resolution have been validated.

Related to \#78693. This PR is independent of \#80371 and the other H3 performance PRs.

\#\# What I'm doing:


- For inputs without NULL values, write directly into a pre-sized output buffer. This avoids per-row data/null-buffer appends and null checks.
- After full H3 cell validation, read the resolution from the documented index field. Construct a parent by replacing its resolution and setting its suffix digits to 7 in constant work, instead of iterating over the removed levels.
- Precompute parent masks once for valid constant target resolutions. Invalid constant targets retain the ordinary validation order.
- For inputs without NULLs, H3\_Resolution returns a constant column only when its input is constant; otherwise it returns a regular column.
- Keep isValidCell authoritative for every nonnull input. Preserve cell-before-resolution error precedence, constant/empty results and the existing nullable fallback. Array and geography functions are unchanged.

\#\#\# Validation

- Official pinned StarRocks Ubuntu development image; GCC 14.3.0, Release, H3 4.5.0. Production \`starrocks\_be\` target passed.

[PR \#80393｜主线 / main](https://github.com/StarRocks/starrocks/pull/80393)

H3\_GridDisk与H3\_ToChildren改为通过H3ArrayBuilder的begin\_row/finish\_row直接写入结果缓冲区，预分配行元数据，去除每行临时std::vector及额外拷贝，并移除对H3输出的逐单元重复校验。

重要性与适用范围：该改动优化H3数组函数逐行求值时的内存分配与拷贝路径，适用于产生大量小数组结果的H3\_GridDisk和H3\_ToChildren查询；输出顺序与NULL/常量/空行为不变，属于运行时性能优化。

官方原文证据（保留基准及适用条件）：
Fixes \#80532

\#\# Why I'm doing:

\`H3\_GridDisk\` and \`H3\_ToChildren\` incur per-row temporary allocations and an extra copy into the array result. Small arrays amplify this overhead.

Related to \#78693. This PR remains independent of \#80371 and \#80392.

\#\# What I'm doing:

- \`H3\_GridDisk\` and \`H3\_ToChildren\` write cells directly into the result buffer through \`H3ArrayBuilder::begin\_row(capacity, zero\_fill)\` / \`finish\_row(count)\`, instead of a temporary \`std::vector\` and a copy.
- Reserve row metadata up front.
- GridDisk asks \`begin\_row\` to zero-fill the output buffer, as required by H3, and compacts \`H3\_NULL\` holes in place.
- Validate the input cell; remove the per-cell \`isValidCell\` re-check of H3's own output.
- \`finish\_row\` retains the cumulative \`uint32\` array-offset check. Output order and NULL/constant/empty behavior are unchanged; the polygon append path is unchanged.

[PR \#80696｜主线 / main](https://github.com/StarRocks/starrocks/pull/80696)

为ExchangeSinkOperator的shuffle分片缓冲增加按driver计的内存阈值，超限时发送并清理非空分片，容量过高则释放；新增会话开关与profile计数器。基准中节点峰值内存由4.69–4.74 GB降至2.73–2.76 GB。

重要性与适用范围：适用于高dop、多目标、宽行shuffle使分片缓冲长期未填满的查询；阈值默认每driver 64 MB且可关闭。基准条件为2 BE、dop 32、1M行×40个VARCHAR(60)列并按非分桶列GROUP BY，节点峰值内存由4.69–4.74 GB降至2.73–2.76 GB。

官方原文证据（保留基准及适用条件）：
 profile did not show the memory.

\#\# What I'm doing:

- \`ExchangeSinkOperator\` tracks the memory its shuffle partial chunks retain. Once that exceeds \`exchange\_sink\_buffer\_flush\_threshold\_bytes\` (BE config, mutable, default 64 MB per driver; \`\<= 0\` disables it):
  - It sends all non-empty partial chunks and clears them, keeping their capacity so the common case does not reallocate.
  - If the capacity they keep is still above half of the threshold, it releases partial chunks until it is not.
- New session variable \`enable\_exchange\_sink\_buffer\_flush\` (default \`true\`, \`TQueryOptions\` field 227) turns the behavior off per query.
- New profile counters:
  - \`ShuffleChunkBufferPeakMemoryUsage\`, \`ShuffleChunkBufferNum\`
  - \`ShuffleBufferFlushCount\`, \`ShuffleBufferFlushRows\`, \`ShuffleBufferReleasedChunks\`
  - \`PeakSerializedChunkBytes\`
  - \`SinkBufferPeakMemoryUsage\`, \`SinkBufferPeakInFlightRpcNum\`, \`SinkBufferPeakRequestNum\`
- Docs for the BE config and the session variable are added in en/zh/ja.

End-to-end check (2 BEs, dop 32, \`new\_planner\_agg\_stage=1\`, 1M rows × 40 VARCHAR(60) columns, \`GROUP BY\` a non-bucket column), toggling only the session variable, 3 alternating runs each:

| \`enable\_exchange\_sink\_buffer\_flush\` | Node peak memory | Shuffle buffer peak (per driver) | Query time |
|---|---|---|---|
| false | 4.69–4.74 GB | ~449 MB | 1.20–1.36 s |
| true (64 MB) | 2.73–2.76 GB | ~75 MB | 1.04–1.13 s |
