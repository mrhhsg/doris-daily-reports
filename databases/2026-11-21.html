PR #130055｜主线 / master

在 s390x 上启用 llvm-libc 数学库，并显式声明浮点硬件能力，使 sqrt 及 asin、pow 内部的平方根计算使用硬件指令，避免回退到软件整数平方根实现。

重要性与适用范围：优化范围限于 s390x 数学运算路径，重点是避免浮点硬件检测缺失导致的软件计算回退；内存操作仍使用 glibc，现有证据未提供查询级性能收益。

官方原文证据（保留基准及适用条件）：
Enable ENABLE_LLVM_LIBC_MATH on s390x.

This gives s390x the same math functions as amd64 and arm64. In particular, floating point calculations round identically, which fixes test failures caused by rounding differences.

This supersedes https://github.com/ClickHouse/ClickHouse/pull/129823 by @jonathan-albrecht-ibm. Their commit is kept as is, followed by a merge of the current master and one more commit that addresses the review: the pinned llvm-libc cpu_features.h does not detect the s390x FPU, so this PR also declares LIBC_TARGET_CPU_HAS_FPU_FLOAT and LIBC_TARGET_CPU_HAS_FPU_DOUBLE. Without them, fputil::sqrt (also used inside asin and pow) falls back to a software integer square root. With them, cross-compiling for s390x gives sqrt as sqdbr + br (6 bytes instead of 506), and asin shrinks from 1026 to 532 bytes. All 46 libllvmlibc sources compile for s390x with -Werror.

On s390x, only the math functions are taken from llvm-libc. llvm-libc has no s390x specializations of the memory functions (e.g. its memcmp compares byte by byte), so memcpy/memmove/memset/memcmp/bcmp/memmem still come from glibc there.

PR #129445｜主线 / master

优化 PREWHERE 对安全别名合取表达式的拆分，在原有位置先应用文本索引提示，与前置过滤结果求交后，再为剩余行读取字符串并执行验证，减少不必要的列读取。

官方原文证据（保留基准及适用条件）：
A text-index rewrite turns a predicate such as s LIKE '%needle phrase%' into an alias for and(H, V), where H is the index hint and V verifies the string. The existing PREWHERE splitter stops at the alias. It reads the string before it can intersect H with the rows that passed the preceding filters.

This change expands safe aliased conjunctions at their original position. For A AND K AND alias(H AND V), the read steps apply A, then K, then H. Only the remaining rows reach V. The splitter keeps the existing filter-group and query-condition-cache boundaries. It preserves named outputs and leaves expressions intact where changing the input rows could change a value or an exception.

Changelog entry (a user-readable short description of the changes that goes into CHANGELOG.md):

Removed a per-row store-forwarding stall from String to number conversions (toFloat64, toInt8OrZero, ...) that appeared on master after storage-backed read buffer padding was introduced.

Description

Since #129052 (master only, not in a release), ConvertThroughParsing installs each row into its ReadBufferFromMemory with BufferBase::setPaddedStorage, which wrote working_buffer and then copied it into internal_buffer. Clang lowers that copy to one 16-byte load of begin/end that spans two 8-byte stores still in flight, which store forwarding cannot serve, so every row waits for the stores to reach L1. setPaddedStorage and setAssumePadded now delegate to the existing setWorkingBuffer, which assigns both buffers from one value. The padding contract of #129052 is unchanged.

Changelog entry (a user-readable short description of the changes that goes into CHANGELOG.md):

The automatic choice of parallel_replicas_mark_segment_size now counts only the replicas that take part in the query: the active replicas of cluster_for_parallel_replicas, at most max_parallel_replicas, the same count the reading coordinator uses. Before, stale replicas of a Replicated database and replicas beyond max_parallel_replicas were counted too, which could choose a smaller segment.

Description

Replaces #109377 with the minimal version agreed there.

Since #107805 the parallel replicas reading coordinator is sized by the active replicas of cluster_for_parallel_replicas, at most max_parallel_replicas. ReadFromMergeTree still passed the registered replica count as total_nodes_count, and chooseSegmentSize divides sum_marks by its square to pick the automatic segment size. Reading Parquet files whose ZSTD pages were written by parquet-java (Spark, Hive, Iceberg Java) or by ClickHouse 26.10 and older is faster: the native Parquet reader decompresses each ZSTD page in one call straight into the page buffer instead of streaming it through a separate window. sum(cityHash64(*)) over ClickBench files written by Spark is 7% faster, and over files written by ClickHouse 26.10 5% faster.
