[PR \#124907｜主线 / master](https://github.com/ClickHouse/ClickHouse/pull/124907)

优化外部 IN 子查询的磁盘集合：按值顺序保存数值、日期、短 FixedString 和元组，打包邻近键，合并读取邻近块且不解压，用 Bloom 过滤跳过块，缓存查找块，并对每块不同键只探测一次。

重要性与适用范围：适用于使用 IN 子查询且集合可能溢写到磁盘的查询；max\_bytes\_ratio\_before\_external\_set 默认 0.5，使集合在查询内存超过服务器或用户限制剩余内存一半时落盘。本改动提升此类集合的构建和查找性能，并提供 Bloom 过滤与缓存的内存上限设置。

官方原文证据（保留基准及适用条件）：
Sets of \`IN\` with a subquery spill to disk by default: \`max\_bytes\_ratio\_before\_external\_set\` now defaults to \`0.5\`, so a set spills once query memory exceeds half of the memory that the server or user memory limits leave. Set it to \`0\` to keep such sets in memory. Sets on disk are built and looked up several times faster: they keep numbers, dates, short \`FixedString\` values and tuples of them in order, pack close keys, read neighboring blocks together without decompression, skip blocks with Bloom filters, cache the blocks that lookups read, and look up each distinct key of a block of rows once. The new settings \`max\_bytes\_for\_external\_set\_bloom\_filter\` and \`max\_bytes\_for\_external\_set\_cache\`, 128 MiB each by default, limit the memory of the Bloom filters and of the cache.
