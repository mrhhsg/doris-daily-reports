[PR \#28793｜主线 / main](https://github.com/duckdb/duckdb/pull/28793)

利用行组 zonemap 统计，将 DuckDB 表扫描的基数估计限制在无法被过滤条件跳过的行组总行数以内，并与原估计取较小值，改善连接顺序及哈希连接构建侧选择。

重要性与适用范围：适用于过滤条件能跳过整组数据的聚簇列查询，可缓解扫描规模高估导致的执行计划失当。边界行组仍按整组计数，不做组内插值；无法跳过行组的非聚簇列不受影响。

官方原文证据（保留基准及适用条件）：
The estimate of a DuckDB table scan with table filters is bounded by the rows of the row groups whose zonemaps can satisfy all of its filters. The row groups come from the existing \`get\_partition\_stats\` callback (what the row group pruner and the \`count(\*)\` statistics shortcut already read at plan time), and the per-row-group check is \`ExpressionFilter::CheckExpressionStatistics\`, the check the scan itself uses to skip a row group. This is a count, not an estimate: rows of row groups the scan will skip are not returned.

A row group that cannot be skipped counts whole. There is no interpolation inside a row group that a range cuts, so the bound is exact to the row group and no finer: a range that ends inside a row group is estimated at that row group's full row count.

The bound only ever lowers an estimate: it is combined with the existing estimate by \`min\`, in \`RelationStatisticsHelper::ExtractGetStats\`, so join ordering and standalone cardinality estimation both see it. A column that is not clustered is untouched: every row group spans the whole range and nothing is skipped. Row groups are counted with the rows the planning transaction can see, so rows it has deleted are not counted and rows deleted by a transaction it cannot see still are.

官方原文证据（保留基准及适用条件）：
\#\# Problem

\`Avro\` (Object Container Files) had no file segmentation engine, so an Avro file was always decoded on a single thread, even with \`input\_format\_parallel\_parsing = 1\`.

\#\# Root cause

\`ParallelParsingInputFormat\` cuts the input into segments and parses each with an independent parser, so a format must tell it where a cut is safe and every segment must be parseable on its own. Avro has neither out of the box: there are no row delimiters, and the schema and sync marker exist only in the file header.
